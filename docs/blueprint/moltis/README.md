# Moltis Skeletons

This directory contains **skeletons** (esqueletos) of all Rust source files from the Moltis project.

## What is a Skeleton?

A skeleton is a simplified version of source code that preserves the API surface while removing implementation details. It contains:

✅ **Kept:**
- Function signatures (name, parameters, return types)
- Struct/enum/union/type declarations
- Trait definitions
- Module declarations
- `use` imports
- Docstrings (`///`)
- Comments and attributes

❌ **Removed:**
- Function bodies (replaced with `...`)
- Struct/enum field implementations
- Impl block bodies
- Test implementations
- Other implementation code

## Example

### Original Code
```rust
/// Add two numbers together
pub fn add(a: u32, b: u32) -> u32 {
    a + b
}

pub struct Calculator {
    value: u32,
}

impl Calculator {
    pub fn new() -> Self {
        Self { value: 0 }
    }

    pub fn add(&mut self, n: u32) {
        self.value += n;
    }
}
```

### Skeleton
```rust
/// Add two numbers together
pub fn add(a: u32, b: u32) -> u32
}

pub struct Calculator {
    ...
}

impl Calculator {
    pub fn new() -> Self {
        ...
    }

    pub fn add(&mut self, n: u32) {
        ...
    }
}
```

## Usage

These skeletons are useful for:

1. **API Documentation**: Understanding the public API surface without implementation details
2. **Migration Planning**: Analyzing code structure when porting to other languages
3. **Code Review**: Quick inspection of module organization and interfaces
4. **Learning**: Studying the architecture and design patterns used in Moltis
5. **Reference**: Understanding how different crates interact with each other

## File Structure

The skeleton directory mirrors the original Moltis workspace structure:

```
moltis/
├── apps/
│   └── courier/
│       └── src/
│           └── main_skel.rs       # Main application skeleton
└── crates/
    ├── agents/
    │   └── src/
    │       └── lib_skel.rs       # Agents crate API
    ├── channels/
    ├── gateway/
    ├── providers/
    └── ... (47 more crates)
```

Each skeleton file is named with a `_skel.rs` suffix to distinguish it from the original source.
